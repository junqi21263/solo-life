# Solo Life Phase 0 基线

本目录是独立的 SDK 58 工程，不迁移历史项目。业务以 SQLite 本地功能开始，账号和单账号备份恢复后置；真正的多设备同步、删除传播和冲突处理仅在明确成为首发需求后实现。账单任务预留可选金额和备注；月末重复与跨时区规则在实现前确认。

## Stitch 到实现

先统一颜色、字体、间距、圆角、组件状态及无障碍规范，再覆盖 Onboarding、Home、Care、Moments、Me、任务编辑和宠物档案。路由放在 `src/app`，通用视觉组件与设计 token 放在路由目录之外；先用 mock 数据验证加载、空、错误、长文本及大字体状态，再接本地服务。按真实设备尺寸、动态字体、VoiceOver、减少动态效果逐页对照验收。Stitch 设计未创建或验收。

## CloudBase DEV 验证清单（未执行）

须先明确并获得独立 DEV 环境授权、区域、Env ID、客户端 Publishable Key、邮箱登录方式和费用；不得使用服务端 API Key 或其他项目环境。

1. 在隔离的最小工程固定并记录 SDK、adapter 和持久化依赖版本，用 development build 检查 iOS 原生编译和初始化；检查安全的会话存储与重启恢复。
2. 验证邮箱注册、登录、退出、过期和网络失败；不要记录令牌。
3. 用两个独立测试账号验证 PostgreSQL 用户身份、RLS 和所有读写操作；跨用户读取、修改、删除必须被拒绝。
4. 验证私有 Storage 的上传、读取、删除、权限隔离、失败重试；检查 iOS 本地文件路径与 SDK 的兼容性。
5. 检查离线、重启和恢复，并记录费用、依赖约束和风险。全部记录为未验证直到真实 DEV 与真机测试完成。

## 阶段质量门槛

每个模块分别记录类型检查、相关业务测试、模拟器构建和运行、本地数据重启保持、离线体验。云权限使用双账号在 DEV 验证；本地通知和视觉在真机逐页验证。阶段完成后在明确的独立仓库建立 Git 提交点，不包含其他项目文件。
